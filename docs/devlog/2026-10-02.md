## 2026-10-02

**目标**：读任务书，定技术栈与架构，搭好项目地基。

### 做了什么

1. **读任务书**。原件 `MajSpirit.pdf` 有个坑：Typora 导出的内嵌字体数字缺少有效
   Unicode 映射，`pdftotext` / `pypdf` 抽取时正文数字会**静默丢失**——"共 136 张"
   会变成"共 张"。改用逐页渲染成图片目视核对，产出 `MajSpirit_转写.md` 作为可靠参照。

   核对出的关键数字：一副牌 136 张（万/条/饼各 4 张 ×9 种 = 各 36 张，字牌 4 ×7 = 28 张）；
   一场四小局，第 N 小局庄家为玩家 N；庄家起手 14 张、闲家 13 张；和牌牌型为
   4 个面子 + 1 个雀头，共 14 张。

2. **定技术栈**。Go + 标准库 `net/http`（1.22+ 的路由增强已经够用，不必上框架）
   + `github.com/coder/websocket` + PostgreSQL + `log/slog`。

3. **确立三个架构决定**：
   - 规则做成纯函数包 `internal/mahjong`，零 IO，可被完整单测覆盖
   - 房间用 actor 模型（每房间一个 goroutine 独占状态），而不是给共享状态加锁
   - WebSocket 只做传输，对局逻辑通过接口回调，可脱离网络测试

4. **定下规则层的表示约定**（写进了 README，实现前先约定好，避免各处自行编码）：
   - 34 种牌编码为 `0..33`，牌的类型表示种类而非具体某张，重复出现即代表副本
   - 紧凑记法 `"123m456s789p11z"`，解析与格式化互为逆运算，测试用例/日志/数据库共用
   - 和牌判定只认"4 面子 + 1 雀头"，顺子限同花色连续三张，字牌不能组顺子，
     **明确不支持七对子**——任务书的简化规则里没有它

5. **搭脚手架**：
   - 目录结构 `cmd/` + `internal/{mahjong,auth,user,store,room,ws,api}/`
   - 每个包的 `doc.go` 写明职责边界与禁止事项
   - `Makefile`、`Dockerfile`（多阶段构建静态二进制）、`docker-compose.yml`（app + PostgreSQL）
   - `migrations/0001_init.sql`：用户、牌局、初始手牌、牌山、每回合动作

### 踩过的坑

- **PDF 抽取丢数字**（见上）。教训：拿到不信任格式的输入时，先做一次小规模
  抽样校验，别直接相信抽取工具的输出。
- Git Bash 的路径转换会把传给 `wsl` 的 `/etc/os-release` 改写成
  `D:/Tools/Git/etc/os-release`，导致读到空文件。正确做法是设
  `MSYS2_ARG_CONV_EXCL='*'`，而不是用老掉牙的 `MSYS_NO_PATHCONV`。
- `while read` 会吞掉**没有换行结尾的最后一行**。校验清单时这个坑会让最后一项
  静默漏检，看起来还"全部通过"。
